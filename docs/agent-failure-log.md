# 에이전트 실패 로그

에이전트(또는 에이전트가 만든 장치)가 **틀렸거나 틀릴 뻔한 일**을 한 줄씩 적는다.
목적은 반성문이 아니라 **어디서 막을지 정하는 것**이고, 지표는 **같은 실수가 다시 나오는가**다.

## 적는 법

- **언제:** 사용자가 지적했을 때, 리뷰·테스트·점검이 에이전트의 판단을 뒤집었을 때, 사고 직전에 멈췄을 때.
- **원인은 환경 쪽으로 쓴다.** "모델이 부주의했다"가 아니라 무엇이 없어서 틀릴 수 있었는지.
- **막는 곳**은 넷 중 하나다. 뒤로 갈수록 강하다.
  `그냥 둠`(한 번이고 싸게 잡혔다) · `문서`(`AGENTS.md`·README) · `스킬` · `장치`(스크립트·테스트·CI)
- **재발하면** 새 줄을 쓰지 말고 그 줄의 "재발"에 날짜를 더하고, 막는 곳을 한 단계 올린다.
  `그냥 둠`이 재발하면 문서로, 문서가 재발하면 장치로.
- **적지 않는 것:** 해소 전 보안 노출, 비밀값, 개인정보. 그런 건 해소 뒤에 적거나 git 밖 `~/study/docs/codex-requests/`에 둔다.
- 범위는 이 저장소 작업이다. 옆 저장소의 실수는 그 저장소에서 적는다.
