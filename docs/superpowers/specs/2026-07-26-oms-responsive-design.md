# OMS 반응형 UI 설계

## 목표

OMS의 고객 화면과 관리자 화면 전체를 375px 모바일부터 데스크톱까지 사용할 수 있게 한다. 기존 시각 디자인과 화면 기능은 유지하며, 페이지 자체의 불필요한 가로 스크롤과 작은 화면에서의 조작 불편을 제거한다.

## 범위

- 공통 내비게이션과 페이지 컨테이너
- 로그인, 회원가입
- 상품 목록과 상품 상세
- 장바구니와 주문서
- 주문 목록과 주문 상세
- 관리자 재고, 보충 요청, 배송 관리

기능 동작, 서버 API, 도메인 모델, 데스크톱 디자인 개편은 범위에 포함하지 않는다.

## 접근 방식

공통 레이아웃은 `static/css/app.css`에서 처리하고, 구조가 고유한 화면만 기존 페이지 CSS에서 보완한다. 새 CSS 프레임워크나 JavaScript 기반 메뉴는 추가하지 않는다.

기존 중단점인 720px과 980px을 재사용한다.

- 980px 이하: 다단 레이아웃과 넓은 폼을 한 열로 축소한다.
- 720px 이하: 내비게이션, 카드, 버튼, 표를 모바일 조작에 맞게 배치한다.

## 화면별 동작

### 공통 영역

- 본문은 화면 너비를 넘지 않는다.
- 내비게이션은 한 줄을 유지하고 내비게이션 내부에서만 가로 스크롤한다.
- 터치 대상과 주요 버튼은 모바일에서 충분한 높이와 너비를 가진다.
- 이미지, 입력 요소, 카드는 부모 너비를 넘지 않는다.

### 고객 화면

- 상품 목록은 모바일에서 한 열로 표시한다.
- 상품 상세의 이미지와 구매 영역은 세로로 배치한다.
- 장바구니의 각 상품 행은 모바일 카드 형태로 재배치하고 수량·금액·삭제 동작을 유지한다.
- 주문서의 주문자·배송지 필드는 한 열로 배치하고 결제 요약은 본문 아래로 이동한다.
- 주문 목록 카드는 한 열로 표시한다.
- 주문 상세의 메타 정보와 상품 표는 작은 화면에서 읽을 수 있게 축소하거나 표 내부만 스크롤한다.

### 관리자 화면

- 재고 요약 카드는 모바일에서 한 열로 표시한다.
- 보충 요청 폼은 모바일에서 한 열로 배치한다.
- 표는 핵심 열을 우선 노출하고 보조 열을 숨긴다.
- 모든 열이 필요한 배송 관리 표는 표 컨테이너 안에서만 가로 스크롤한다.
- 일괄 처리 도구와 버튼은 화면 밖으로 밀려나지 않는다.

## 접근성

- 기존 시맨틱 HTML, 레이블, 키보드 동작을 유지한다.
- 콘텐츠를 CSS로 숨길 때 모바일 작업에 필요하지 않은 보조 정보만 대상으로 한다.
- `prefers-color-scheme` 대응을 훼손하지 않는다.

## 검증

정적 테스트로 공통 반응형 규칙과 주요 화면별 모바일 규칙이 유지되는지 확인한다. 테스트를 먼저 추가하고 실패를 확인한 뒤 CSS를 수정한다.

수동 검증 뷰포트:

- 375×812: 모바일 기준
- 768×1024: 태블릿 기준
- 1280×800 이상: 데스크톱 회귀

각 크기에서 고객 상품·장바구니·주문 상세와 관리자 재고·보충 요청·배송 관리 화면을 확인한다. 페이지 전체 가로 넘침, 잘린 버튼, 겹친 텍스트, 사용할 수 없는 입력 요소가 없어야 한다. 마지막으로 OMS 전체 Gradle 테스트를 캐시 없이 실행한다.
